# ADRs

Architecture Decision Records (ADRs) capture important technical decisions in this repository.
Each ADR should explain the context, the decision, and the consequences.
New ADRs should use sequential numbering, for example: `0001-tenancy-and-data-model.md`.

## Superseding
When a later decision replaces an earlier one, do not edit or delete the earlier
ADR. Change its `Status` to `Superseded by ADR-NNNN` and record the new decision
in the new ADR. The record is a history of what was decided and why, including
decisions that were later reversed; rewriting it destroys the reasoning behind
choices that still constrain the codebase.
